## 先读这一条：为什么大多数旨"跑完但不及格"

质门判定规则⑤（`prompts_finance.py`）：

> 输入未提供损益表/税务/债务数据，而输出**明确写"无法审计计算/待补证/不适用"**的，属于诚实边界，**不得判 fail**。

所以只有两条活路：

1. **给数字** → 能算 → 高分。
2. **不给数字，但让它老实说"没数据、算不了"** → 按规则⑤也不该判 fail。

**死路是第三种：没给数字，还用通用框架把版面填满。** 硬核查 `C1数字勾稽 / C3事实有据 / C4结构完整` 会整排 FAIL，总分封顶 ≤3。

> 实测：一道「评估本季供应商集中度风险」（无供应商名单、无采购额、无账期）→ 质量分 **1.33**，`release_gate=blocked`。
> 系统从头到尾都是对的，它只是在忠实地告诉你「你没给我数据」。

**推荐旨的共同点：带数字、带约束、带边界。**

## 密旨（保密单线 · 只调一个部，不走军机处）

密旨的部由 `selectSingleDept` 按**第一个命中的关键词**决定，且受**部级泄密白名单**约束
（`secret-dept-guard.ts`：单线直调只准触达 1 个部；越界 fail-closed 拒发）。
**密旨不受高风险强制会审约束** —— 保密单线本身就是受限通路。

### ⑥ 密旨 · 户部（现金流）

> 现金余额2400万，未来90天刚性支出1800万，应收6个月内可回款900万。评估是否需要提前融资，给出止损点与三档情景。

- 命中户部关键词：`现金`、`投资`
- "止损点/退出阈值"是户部 `mustCheckGaps` 里明确要求的项（`ministry-registry.ts`），主动给它 → 少一条缺证

### ⑦ 密旨 · 刑部（合同风险）

> 合同条款：30%预付/60%验收/10%质保18个月，违约金每日0.5%，知识产权归客户，争议在客户当地法院。评估风险与可谈判空间。

- 命中刑部关键词：`合同`、`预付款`、`违约`
- 蜂群：`legal`（基线 7.5）
- 条款全是硬数字/硬条件 → C3 事实有据站得住
- 出处：`golden_cases/legal.json` 原话

### ⑧ 密旨 · 财务闭环（唯一会自动外部取证的路径）

> 用 SEC 官方来源评估 MSFT 当前估值风险，只做内部观察，不给买卖建议。

- 去向：**被 `parseFinanceIntelCommand` 截走** → 四站管线：上书房立案 → **锦衣卫采证** → 户部奏折 → 丞相回奏
- 触发条件：命中 `SEC` + 一个 1–5 位大写股票代码 + `估值/风险/投资/合理` 之一
- 这是**唯一**会去外部真取证（Tavily/SEC）的入口
- 部级泄密白名单：`{锦衣卫, 户部}`（2026-07-13 裁定：锦衣卫采证是户部办案的自带前置工序，不算"召其它部"）

## 三个坑（都是代码里读出来的）

### 1. 拦截器排在部门路由**前面**

`confirmDraftedDecree` 里的顺序（`ShangshufangPage.tsx`）：

```
PACK闭环 → 户部财务状况 → 财务报表 → finance-intel → (才轮到) 部门路由
```

你的旨里只要出现：

- `PACK / 电芯 / 电池包 / 储能` → 被 PACK 闭环抢走
- `财务状况 / 经营状况 / 现金状况 / 当前财务` → 被户部即时回奏抢走
- `财务报表 / 三表 / 利润表 / 资产负债表` → 被报表闭环抢走
- `SEC + 股票代码` 或 `估值/值不值得投/ROI/回收期/现金流/预算/成本核算` → 被 finance-intel 四站抢走

**不管你点的是下旨还是密旨。**

### 2. 高风险词 = 下旨强制军机处

`报价/合同/股权/付款/预付款/独家/违约金/签约/对外承诺/客户承诺/供应商锁定/不可逆`

下旨时**不能**单部直办（要过风险披露 + 人工确认门）。密旨不受此限。

### 3. 蜂群质量分抖得厉害

同一类问题实测：**1.33 / 1.94 / 5.0 / 1.8 / 2.69**。

**给的数字越多、约束越硬，分越稳。** 空泛的"评估一下 XX 风险"基本必挂。
