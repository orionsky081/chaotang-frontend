# 前端主库 → 后端 迁移蓝图(2026-07-17 立)

> 目标:**前端不再有数据库**。`.chaotang-main-dev.db`/Turso 的 37 张表全部迁到后端,前端所有持久化改为 HTTP 调后端。
> 这是**不可逆架构改动**,反转 §13.2.9「前端咨询+本地持久化 / 后端产线」的旧切分——以后前端每次下旨/裁决/归档都是一次后端往返。

## 已定决策(2026-07-17,用户确认)

1. **存储底座 = 后端 SQLAlchemy ORM**(`backend/src/db/`,与 flow_store 同栈,alembic 管迁移)。
2. **节奏 = 增量分阶段**(P1→P4,每阶段独立可上线/回滚/验证,禁 big-bang)。
3. **存量数据 = 清盘从零**(只迁 schema,不迁 dev 数据;后端从空库起)。

## 关键现实:不是纯从零,是「协调 + 补建」

- **A · 已有后端 model(7,协调)**:`tasks` `memorials` `shiguan_archives` `emperor_decisions` `decision_tasks` `court_reviews` `court_loop_runs`
  → **当心前后端同名表 schema 不一致**;迁移时以后端为准,前端字段对齐后端,差异列补进后端 model + alembic。
- **B · 后端从零建 model(30)**:`court_issues` `decision_briefs` `department_memorials` `intel_signals/intel_evidence_packs/intel_signal_routes/intel_snapshots/intel_source_track_record` `draft_edicts` `execution_runs` `imperial_instructions` `decisions` `archive_records` `bingbu_competitors/recommendations/swot` `hubu_projects/summary` `forecast_scenarios` `lessons` `manor_metrics` `medical_news` `health_profiles` `ima_knowledge_documents` `shangshufang_im_messages` `swarm_session_links` `tenants` `tenant_members` `department_review_runs` `agent_runs`

## 分阶段(按表组,每组一个可上线切片)

- **P1 · 上书房闭环核心**:`court_issues`(B)`decision_briefs`(B)`department_memorials`(B)`tasks`(A)`memorials`(A)`draft_edicts`(B)`emperor_decisions`(A)`decisions`(B)`execution_runs`(B)`imperial_instructions`(B)
  → 最承重,承载下旨→裁决→执行。**先迁这组**。
- **P2 · 飞轮**:`shiguan_archives`(A)`archive_records`(B)`court_reviews`(A)`court_loop_runs`(A)`decision_tasks`(A)`lessons`(B)`department_review_runs`(B)`agent_runs`(B)
  → 归档→召回复利归后端才是正主。
- **P3 · 情报**:`intel_signals` `intel_evidence_packs` `intel_signal_routes` `intel_snapshots` `intel_source_track_record`(全 B)
- **P4 · 六部/其它**:`bingbu_*` `hubu_*` `forecast_scenarios` `manor_metrics` `medical_news` `health_profiles` `ima_knowledge_documents` `shangshufang_im_messages` `swarm_session_links` `tenants` `tenant_members`

## 每张表的统一迁移工序(pattern,照此复制)

1. **后端 model**:`backend/src/db/models.py` 加/对齐 `class Xxx(Base)`;alembic 生成迁移。
2. **后端 endpoint**:`backend/web/routers/` 加读写路由(REST),鉴权走后端 JwtAuthGuard(硬约束:验签归后端),按 `user_id`+`tenant` 隔离(沿用前端 IDOR 归属语义)。
3. **前端改调后端**:该表对应的前端 store/route(`primary-store`/`finance-intel-loop-store`/`archive-store`/…)从 `db.execute` 改为 HTTP 调后端;`sourceLabel` 由后端返回。
4. **删前端 DB 依赖**:该组全迁完后,删对应前端 store 的 SQL + `turso.ts`/`schema.ts` 里该表 DDL。
5. **双门**:前端 `tsc`+`next build`;后端 `pytest`+`alembic upgrade head`+`validate_flows`。
6. **飞轮/缺证门等承重逻辑**(recall-guard/finalizeDecisionSource/evidence-gate)随其表一起过后端,回归断言同步搬。

## 收尾判据(全 4 阶段done 后)

- `turso.ts` 的 `file:./.chaotang-main-*.db` 回退**整段删除**;前端无任何 `db.execute`。
- `grep -rn "db.execute\|getDb\|ensurePrimaryDbReady" frontend/src/app` → 0 命中。
- 前端只剩「HTTP 调后端」一条持久化通路(§13.2.9 反转后的新 SSOT:后端是唯一库)。

## 风险 / 看守

- **同名表 schema 漂移**(A 组 7 张):迁移前逐张 diff 前端 DDL vs 后端 model,不一致处必须显式对齐,别默认等价。
- **IDOR 归属**:前端现在按 `court_issues.user_id` 判归属(§本会话 404 真因);后端 endpoint 必须保留同款归属校验(非 owner → 404)。
- **飞轮命门**:`synthetic`/`finalizeDecisionSource`/召回过滤(recall-guard SQL)搬后端时,回归断言(飞轮心跳)必须一起搬,别只搬表。
- **延迟/离线**:前端无本地库后,后端不可达=无法下旨/裁决;需明确降级态(不再有本地兜底)。
