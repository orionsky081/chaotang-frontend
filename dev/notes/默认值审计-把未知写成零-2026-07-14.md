# 默认值审计：把"我不知道"写成"零" · 2026-07-14

> **一天之内栽了四次。** 都是同一个病：**缺省值把"未知"写成了一个具体的数，于是一个假事实诞生，并开始指挥决策。**
>
> 这不是抠细节 —— 这四次里，有一次让我误判"PACK 蜂群坏了"，有一次让一道安全门在没有依据时选择放行。

**共同点：一个为了方便而设的默认值，制造了一个假事实。**

而假事实比缺失更危险 —— 缺失会让人去找，假事实会让人**停止寻找**。

---

## 判据（以后写默认值时问这一句）

> **这个 0 是真的 0，还是"我不知道"？**

- 真的 0（计数器、累加器初值、真实的零金额）→ 写 0 没问题。
- "我不知道" → **必须是 `None` / `null` / `undefined`**，让下游被迫处理它，或者 fail-closed。

**尤其是这三类，一律不许用零兜底：**

1. **评分 / 置信度** —— 0 分看起来像"很烂"，而不是"没测过"。
2. **金额 / 锚点 / 控制数** —— 0 元看起来像"没有欠款"，而不是"没拿到数据"。
3. **安全门的输入** —— `ctrl == 0 → 放行` 这类写法，等于让门在断电时自动打开。

> 那个 `Math.max(0.72, ...)` 干了两件坏事：缺值时凭空造 0.72；**有值但低于 0.72 时抬高到 0.72** ——
> 证据再烂，界面上的置信度也永远不低于 72%。这是在**制造确定性**。
> 改成可空后，TypeScript **当场抓出两处会印出编造数字的地方**（界面 + 写进圣旨正文）。这就是可空的价值。

## 最该记住的一句

**缺失会让人去找，假事实会让人停止寻找。**

我看到 `0.00` 的第一反应是"PACK 蜂群坏了" —— 而那个 0 只是一个善意的默认值，为了"确保门控触发"。
它没有骗任何代码，它骗的是**读它的人**。

> 默认值是这个代码库里**最没人审查、却最会撒谎**的东西。
