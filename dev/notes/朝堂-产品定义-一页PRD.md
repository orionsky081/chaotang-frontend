# 朝堂OS · 一页产品定义（V1 · 2026-08-01）

> 状态：当前产品定位真相源。详细业务契约以
> `朝堂OS-V1-报价准入试点章程-2026-07-30.md` 为准。
> 本页覆盖 2026-06-28 的“钱 / 单 / 人 / 情报”宽定位；横向经营决策 OS 只保留为第二幕愿景。

## 1. 一句话定位

**朝堂OS 是面向 20–300 人新能源设备项目制企业的正式报价准入回奏台：在报价发给客户前，把成本、毛利、BOM、交付、账期与合同责任汇成一页可审计的准奏、补证、驳回或业务例外建议，交由老板最终拍板。**

V1 行业边界是新能源设备销售与项目交付。储能设备 / 电池 PACK 只作为首批设计伙伴的候选获客标签，不写进永久产品边界，也不改变冻结章程的 20 案验证规模。

## 2. 首个 ICP 与购买时刻

- 章程范围：20–300 人的新能源设备项目制 B2B 企业。
- 首轮销售名单假设：先找 50–150 人、年营收约 5000 万–2 亿元、老板仍亲自拍板非标报价的企业，避免首批样本的采购与部署条件差异过大。
- 硬筛选：每月不少于 10 笔正式项目报价；一笔报价需要至少 3 个部门参与；包含 BOM、交付、账期、质保或赔偿责任；最近 12 个月有至少 10 个可复盘历史案例。
- 经济买家：老板 / 总经理。
- 内部牵头：总经办、老板助理或有跨部门协调权的试点运营官。
- 使用者：销售负责人、项目负责人；必要参审人是财务、技术 / 交付与法务负责人。
- 触发时刻：客户催促在 24–72 小时内发正式报价，同时出现非标 BOM、低毛利、长账期、高垫资、交期冲突或异常质保 / 赔偿条款。

反向排除：若一笔报价可由一人 30 分钟完成、没有跨部门证据与交付责任，该企业不进入 V1 试点。

## 3. 客户要完成的任务（JTBD）

> 当客户催我尽快发出一笔高风险、非标项目报价时，我希望不用逐个追人、开多轮会，就能拿到一个有证据、有冲突、有责任边界的主建议，以便决定这单是否值得报、按什么条件报，并在事后知道当初判断是否正确。

章程中的 10 / 20 分钟只计算“完整且经人工确认的证据包进入系统 → 机器形成待审回奏”的系统耗时，不包含销售补证、参审人反馈和有权人裁决等待。试点必须另记“发起 → 最终裁决”的业务周转时长，并与客户原流程基线比较。

客户购买的结果不是“AI 分析”或“一套数字朝廷”，而是：

1. 少报一笔亏损、不可交付或责任失控的订单。
2. 缩短跨部门报价会签时间。
3. 把低毛利、长账期等业务例外写清金额、责任人和复核日期。
4. 冻结当时证据与判断，在签约、交付和回款后形成偏差卡。

当前替代方案是微信群 / 电话催办 + Excel 成本与 BOM + 邮件 / 会议 + 老板凭经验拍板；更成熟企业会叠加 ERP、CRM 或 OA 审批。朝堂OS V1 不替代这些系统，只负责它们没有负责的“最终准入建议 + 证据边界 + 结果复盘”。

## 4. 最小可卖闭环

```text
报价草案 + 经确认的证据包
  → 户部核查毛利、成本与数字一致性
  → 按风险召集工部 / 刑部等最少必要参审方
  → 军机处保留冲突、补证并执行质量门
  → 丞相给出一页主建议
  → 有权人准奏 / 补证 / 驳回；业务例外由运营官按章程手工执行双确认
  → 史馆签封归档
  → 运营官在签约 / 交付 / 回款节点人工回填，系统据此追加偏差卡
```

当前代码已经具备案件持久化、证据门、会审、人工裁决、签封归档和高风险离线签章骨架；但报价入口、结构化报价证据与正式案件链仍需在真实试点中证明完全贯通。当前只可销售**由试点运营官陪跑的报价准入验证服务**，不得宣称客户可自助运行、自动报价、自动外发或已成为生产审批系统。

试点运营官当前负责收集与编号材料、把报价草案和证据包录入正式案件、核对模型提取字段、组织人工参审与业务例外双确认、催办结果回填。`/api/ready` 报价试点 ready 且 blockers 为零只是生产放行的必要条件，不是充分条件；还必须通过冻结章程的历史盲测、正式报价端到端、真实证据包、运行 truth label、恢复与可观测证据以及 30 天 Go / No-Go。

## 5. 价格实验（不是销售承诺）

- 待测试报价：**人民币 39,800 元 / 4 周**，仅用于 3 次合格经济买家报价访谈，不代表已批准套餐。
- 概念范围：历史盲测、阈值配置、运营陪跑、新报价影子运行和结项复盘；正式案例数、双方响应 SLA、合格材料清单、停止条件与交付物必须在首份合同前单独冻结。
- 阶段门：历史盲测未通过冻结章程的 5 项验收时，客户可停止，不进入新报价阶段。
- 不承诺：赢单率、利润增长、自动对外发送、真实多 Agent 增益、追加免费服务或 4 周内不可归因的长期经营结果。

价格只在至少 3 位合格经济买家完成报价测试、至少 1 家签署并支付试点后，才从“假设”升级为正式报价。

## 6. 30 天成败标准

全部安全门、普通 / 复杂任务双 SLA 和业务指标直接引用 V1 试点章程的 `Go / No-Go`，本页不复制或降低门槛。产品发现额外记录三项不可刷绿的证据：

- 系统发现的风险是否让老板改变了准入结论、报价约束或责任安排，并记录可量化风险敞口。
- 从完整证据包到待审回奏的系统耗时、从发起到最终裁决的业务周转时长，分别相对客户原流程改善多少。
- 商业验证只认已支付试点或已签署合同，不把无约束“年约意向”计为通过。

若老板不愿把下一笔真实报价交给系统，即使界面、蜂群和演示全部跑通，也判定产品切口尚未成立。

## 7. 发现树与先验假设

| 目标 | 机会 | V1 解法 | 最快实验 |
|---|---|---|---|
| 30 天内让老板持续把正式报价交给系统 | 报价材料分散、缺项发现太晚 | 最低证据包 + 缺证门 | 1 个已亏损历史案盲测；5 个新案观察补证率 |
| 同上 | 跨部门意见没有一个对老板负责的主结论 | 最少必要会审 + 一页主建议 | 对照原审批结论；记录老板阅读与裁决耗时 |
| 同上 | 业务例外与事后结果不可追责 | 双确认 + 不可覆盖归档 + 偏差卡 | 历史揭盲；在签约 / 交付 / 回款节点回填 |

最高风险、最低确定性的假设按以下顺序验证：

1. 合格企业愿意在客户催促时提交完整证据，而不是继续走微信群。
2. 一页回奏能改变或加速老板的真实裁决，而不只是“看起来专业”。
3. 至少一家客户愿为 4 周受控试点实际支付 39,800 元。
4. 系统发现的风险或效率改善足以支持续费，而不是一次性咨询价值。

## 8. 明确不做

- 不再以“千万以下、没有专业团队的一切小老板”为首发 ICP。
- 不把钱、单、人、情报四条线同时作为 V1 产品。
- 不把 24 个蜂群、六部齐全、庄园或页面数量当对外卖点。
- 不做英超购票、旅行、C 端个人决策、自动下单等邻近场景。
- 不替代 CRM、ERP、OA；不自动发报价、签合同、付款、采购或修改政策。
- 不在 20 个案例完成前扩招聘、营销、投资、竞争情报或第二条旗舰流程。

朝堂隐喻保留为产品体验和品牌记忆；对外销售主语始终是“项目正式报价准入”。
