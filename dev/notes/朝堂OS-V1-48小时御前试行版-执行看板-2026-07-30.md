## 1. 黄金案例契约

一个 `caseId` 必须贯穿：

```text
证据包
  → 上书房拟旨
  → 丞相 Mission
  → 户部/工部/刑部分奏
  → 锦衣卫/钦天监条件触发
  → 军机处会审
  → 一页回奏
  → 皇帝裁决
  → 史馆冻结奏折与预测
  → 揭盲
  → 结果追加与偏差卡
```

黄金案例在 H0–H4 只建立契约和失败测试，不读取揭盲结果。

## 2. Agent 编制与文件边界

### A0 · 主集成 Agent

独占职责：

- 跨栈契约与状态机。
- `caseId`、证据版本、规则版本、成本和阶段状态的统一轨迹。
- 黄金案例测试骨架。
- 各 Agent 合流和最终发布门。

独占区域：

- 前端共享契约目录。
- 后端丞相运行时契约、命令、状态归约和主服务组合。
- 前后端主链 API 契约。

禁止：

- 在 H4 前把共享契约修改权交给其他 Agent。
- 为赶时间新建第二套报价控制平面。

### A1 · 上书房前端 Agent

职责：

- 证据包录入、缺证提示和人工确认。
- 任务进度、累计成本和剩余时间。
- 一页回奏、触发理由和未完成项。
- 准奏、驳回、补证按钮。
- 预测快照和偏差卡只读呈现。

主要区域：

- 上书房功能组件和页面。
- 对应的前端接口适配。
- 上书房浏览器 E2E。

禁止：

- 在浏览器内重新实现部门判断、触发规则或审批授权。
- 修改共享契约；发现缺口只能提交给 A0。

### A2 · 部门与横向机构接线 Agent

职责：

- 接入现有户部报价/现金流、工部交付/BOM、刑部合同能力。
- 实现锦衣卫、钦天监条件触发适配。
- 输出统一分奏、证据引用、风险和触发原因。
- 强制参审未完成时失败关闭。

主要区域：

- 报价裁决、现金流、真实部门引擎。
- 锦衣卫证据核验和钦天监 foresight 适配。
- 相关后端路由和目标测试。

禁止：

- 用模型自行制定企业阈值。
- 让钦天监预测直接产生硬否决。
- 修改皇帝授权或史馆归档边界。

### A3 · 史馆 Agent

职责：

- 时间切片召回，排除目标案例和未来数据。
- 冻结不可变奏折与预测快照。
- 只追加真实结果。
- 生成预测值与实际值偏差卡。
- 生成学习候选，但不自动修改政策或提示词。

主要区域：

- 史馆归档服务、存储与结果观察。
- 史馆页面的数据适配和目标测试。

禁止：

- 读取揭盲包明文。
- 覆盖历史预测、证据或规则版本。
- 用模型自评分更新可靠率。

### A4 · QA/红队 Agent

职责：

- 从 H0 开始并行编写攻击案例。
- 检查越权、租户隔离、揭盲泄漏、数据穿越和快照篡改。
- 验证强制机构不可被跳过。
- 执行真实浏览器黄金闭环。
- 汇总最终五项验收证据。

主要区域：

- 后端目标测试、攻击集。
- 前端 E2E。
- 发布门与验收记录。

禁止：

- 修改产品逻辑来让测试变绿。
- 使用前端 mock 分数证明后端可用。

## 4. 五项验收台账

| # | 验收项 | 机器证据 | 人工证据 | 状态 |
|---|---|---|---|---|
| 1 | 老板用真实证据发起首案 | `caseId`、证据版本、拟旨记录 | 上书房现场操作 | 待验 |
| 2 | 路由及横向机构理由可见 | 已具备：路由计划、规则版本、触发记录 | 老板能解释为何触发/未触发 | 机器证据通过，待现场 |
| 3 | 20分钟/15元内形成一页回奏 | restricted runtime、逐案 checkpoint、观测零 provider 成本与签名汇率门已具备 | 回奏能直接支持裁决 | 机器路径通过，待真实首案计时 |
| 4 | 可准奏/驳回/补证且无外部动作 | 66 项 egress census、运行时 deny、签名 coverage manifest 与幂等 outbox 已具备 | 老板完成一次裁决 | 机器路径通过，待现场 |
| 5 | 冻结预测并在揭盲后生成偏差卡 | 已具备：不可变摘要、append-only 结果、偏差记录 | 运营官确认未提前泄题 | 机器证据通过，待现场 |

五项必须全部通过。任一项失败，整体状态为“不通过”。

## 5. 立即停止条件

- 越权访问或跨租户读取。
- 揭盲包、原审批结论或真实结果提前泄漏。
- 伪造证据被系统采信为正式事实。
- 锦衣卫或钦天监强制触发被静默跳过。
- 奏折、预测快照、证据或规则版本可被覆盖。
- 自动发送报价、签约、付款或发生任何未授权外部动作。

停止后只允许：

- 保留隔离环境。
- 保存可审计日志。
- 形成缺口回奏。
- 修复后重新开始一次完整的五项验收。

## 8. 已知生产前缺口

- 正式证据需使用 `LIVE` manifest，由材料责任人的离线 Ed25519 私钥签署，并在服务端登记对应公钥；私钥不得进入朝堂OS环境。
- 报价 live 部门调用已有 canary reservation/transport/artifact 适配器，但仍需从逐案人工批准的 Canary authority 启动，逐轮落 case binding；没有 authority/artifact 时继续失败关闭。
- USD/CNY 汇率 artifact 已可冻结、签封和复验；正式试点仍需配置真实户部签署人和有效汇率制品。
- 全部已声明外部出口已由 egress census、append-only effect ledger、签名 coverage manifest 和运行时 deny 共同约束；剩余工作是正式环境逐项核对清册与签名权，而不是继续补一套台账。
- confirm 已具备 durable checkpoint、稳定幂等键、lease、outbox、崩溃恢复和结果重放；正式环境仍需用目标 PostgreSQL 与真实进程中断完成现场恢复验收。
- 需要指定运营官、揭盲包保管人和老板验收账号，并完成一次隔离环境现场闭环。

- 自动修改政策、触发规则、部门权重或提示词。
