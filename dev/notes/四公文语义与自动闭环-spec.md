## 01 · 奏折 与 回奏 —— 一直没分清的那对

**一句话：奏折是一个部门的原材料，回奏是丞相汇总多份奏折后的成品决策书。**

| | **奏折 · Memorial**（原材料·单部门产物） | **回奏 · Decision Brief**（成品·御前裁决书） |
|---|---|---|
| 是什么 | 一个部门的专业产物（户部奏折＝财务意见；锦衣卫奏折＝情报） | 丞相把 N 份奏折＋证据＋缺证＋风险汇总成的裁决面板 |
| 数据表 | `department_memorials`（一行＝一部门一折） | `decision_briefs`（引用 `memorialIds[]`） |
| 谁产出 | 部门蜂群，自动（`from-swarm`） | 丞相汇总，自动（`from-memorial`） |
| 皇帝能做 | **存档**——仅认可留档，不处置六部 | **采纳 / 补证 / 复核 / 驳回 / 追问**——真裁决 |
| 事件 | `hubu.memorial.archived` | `archive.created` / needs_evidence … |

**关系链：** 多份 **奏折** →（丞相 `from-memorial` 汇总）→ 一份 **回奏** →（皇帝裁决）→ 归档

## 02 · 四公文 × 按钮 × 后果 真值表

> 正文按钮谁点全是皇帝；丞相是内置控制层，不出现按钮。

| 公文 | 正文按钮 | 后果 | 事件流 |
|---|---|---|---|
| **圣旨**（皇帝发文） | `下旨` | 丞相自动调度（单部门直办 / 多部门入军机处会审） | `edict.confirmed → chancellor.routed` |
| **密旨**（皇帝·机密） | `下旨` | 单线调度，**禁入军机处**（会审＝广播＝泄密），史馆封存 | `edict.confirmed(secret) → chancellor.routed` |
| **奏折**（部门产物·只读） | `存档` | 认可此折并存史馆（记忆动作，**不处置**，避免微操六部） | `hubu.memorial.archived` |
| **回奏**（丞相回奏·收口） | `采纳 / 补证 / 复核 / 驳回 / 追问` | 结案归档 / 补证重跑 / 复核 / 驳回记教训 / 追问 | `archive.created · needs_evidence · …` |

## 03 · 目标：全自动流转，尽在上书房

> 一次下旨，各站自动流转、逐站在上书房点亮；皇帝只在回奏处落一次手。
> 转派（采证→户部、奏折→回奏）不需人工。

```
立案 →(自动)采证 →(自动 from-swarm)户部奏折 →(自动 from-memorial)回奏 →【★皇帝裁决·唯一人工】→(自动)归档→召回
上书房   锦衣卫          户部                  丞相              回奏面板                史馆
```

- **自动流转**（蓝）：后端级联 + 上书房实时点亮（立案 / 采证 / 户部奏折 / 回奏）。
- **唯一人工触点**（金）：御前裁决（回奏面板）。

## 04 · 待对齐的三笔债

现状里让"奏折 vs 回奏"混淆、也是落地前要拍板的地方。

1. **⚠ 同一个"准奏"，两种后果**
   奏折的准奏＝**留档**（`hubu.memorial.archived`），回奏的准奏＝**结案归档**（`archive.created`）。
   建议按 01 表改名：奏折键叫「存档」、回奏键叫「采纳」，不再都叫"准奏"。

2. **⚠ 回奏按钮：wireframe 与代码不一致**
   wireframe 定的是 `准奏 / 批示 / 驳回 / 会审`，代码实际是 `采纳 / 补证 / 复核 / 驳回 / 追问`。
   需二选一对齐——建议保留代码四键，补一个「会审」打回军机处。

3. **⚠ 自动闭环已成立，但"看不见"**
   `complete` 级联其实已自动跑完 采证→户部奏折→回奏，只在裁决处停；但它是一次阻塞大调用，
   上书房等它跑完才出结果、中间不逐站点亮。
   **P1 就是把这条已在自动跑的链实时投影到上书房 case-spine。**
